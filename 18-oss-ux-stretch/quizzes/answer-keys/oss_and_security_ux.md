# Quiz answer key — oss and security ux

Use only after attempting the quiz questions.

1. Open-source software — read contributing guide / existing issues; reproduce locally so maintainers are not debugging your environment.
2. Habituation / alarm fatigue; users click through without understanding missend risk or consequences.
3. Learning-purpose honesty; no harvesting real credentials or attacking real users — disclose simulation purpose in UI and campaigns.
4. No — optional stretch. Clear labeling avoids fake seniority claims on the rubric.
5. Users may silence real threats permanently; prefer timed snooze + clear re-enable and severity-matched confirmation.
6. Explain intent, risk, and how reviewers can verify (commands/tests/screenshots of the warning states).
